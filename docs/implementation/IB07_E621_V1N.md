## Category DOM observation

The native tag-list structure was subsequently captured.

Observed contract:

- root: `section#tag-list`;
- category headers: `h5.tag-list-header[data-category]`;
- category lists: `ul.tag-list.<category>-tag-list`;
- canonical tag rows: `li.tag-list-item[data-name][data-category][data-count]`.

Observed native categories include:

- artist;
- copyright;
- character;
- species;
- general;
- meta.

The current Post model has dedicated fields for artist, character, copyright, general and meta, but no species field. Production therefore maps only the model-supported category fields and leaves species represented through `allTags`; it is not relabeled as general.

Commit:

- `c065308a0780d71d48b33dd5efad925190852fdf`

Production source blob:

- `2b929fdb0fc6363e25ecbdd452e3b2c61a50d9ca`

The parser uses the observed `data-category` and `data-name` attributes directly. It does not infer categories from heading text or link text.

The previously speculative Source-element parser was removed at the same time. Although Source is visibly present in the post Information block, its exact DOM element contract has not yet been captured. Source therefore remains UNKNOWN in production until observed.
