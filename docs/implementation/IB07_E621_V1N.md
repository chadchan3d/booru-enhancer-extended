# IB07 V1-N — e621.net native listing observation

**State:** listing/native facts PASS; post observation OPEN; pagination continuation OPEN  
**Observed route:** `https://e621.net/posts`

## Three-card observation

Three visible native `article.thumbnail` cards were captured.

The deployed card markup exposes, directly on the article:

- `data-id`;
- `data-tags`;
- `data-rating`;
- `data-file-ext`;
- original `data-width` / `data-height`;
- original byte `data-size`;
- created-at;
- score and favorite count;
- MD5;
- `data-preview-url`;
- `data-preview-webp`;
- `data-sample-url`;
- `data-file-url`;
- preview dimensions.

The native card link is `/posts/<id>`. The rendered thumbnail is a `picture` with WebP and JPEG preview sources.

Observed public post IDs:

- 6736194
- 6736192
- 6736191

Observed original media examples span JPG, PNG and WebP.

## Native rendition contract

For the observed listing context, all four useful rendition/identity facts are already present without a request:

- post/native URL;
- preview URL;
- sample URL;
- original file URL.

Original width, height, byte size, extension, MD5, rating, score, favorite count and tags are also already present.

Therefore e621 listing enrichment does not need `/posts.json` merely to obtain those facts.

## Category limits

The listing's flat `data-tags` value provides all tags but does not itself classify artist/character/copyright/general/meta categories. Those category-specific fields remain unknown from this listing capture.

Source URL is also not present in the captured card attributes.

Account-relative `data-is-favorited` / `data-vote` were present, but no favorite/action strategy is admitted from that fact alone.

## Pagination

The passive capture returned no matched native next link.

This does not prove that e621 has no native continuation control; it proves only that the capture did not observe one with the tested selectors.

Accordingly:

- no arbitrary numeric page reconstruction is admitted;
- existing/native navigation remains authoritative;
- e621 infinite-scroll synthesis must not invent `page=2` from the bare `/posts` route.

## Scoped conclusion

**e621 listing/native metadata strategy: PASS.**

No resolver request is required for observed listing rendition facts.

Still OPEN:

- e621 post-page native facts;
- pagination continuation strategy;
- favorite/action behavior;
- any endpoint strategy for fields not present natively;
- all e926 behavior.
